# Changelog

Fixes go on `main`. Chapter tags never move once published; a chapter whose code had to change gets a new tag alongside the old one, such as `ch08-r2`.

## Unreleased

- Security: CSRF protection is back on everywhere except when `APP_ENV=local`. Tags `ch09` and `ch10` exempted `login` and `support/*` in every environment so the book's `curl -b cookies.txt` flow works; `main` now exempts only `login` and `support/ask`, and only locally. In any other environment, send the `XSRF-TOKEN` cookie value back as the `X-XSRF-TOKEN` header. Do not deploy the `ch09` or `ch10` tags as they stand.
- Fix a flaky `help:search` test at and after `ch06`: `RefreshDatabase` rolls back the bulk inserts of the `help:embed` tests, which leaves dead entries in the HNSW index, and an approximate index scan over a handful of rows could then miss the right chunk. The two search tests now turn off index scans for their transaction so they compare exactly; no application code changed. Test-only, so the `ch06` tag is unaffected.

## ch15

- Retrieval-augmented generation. `SupportAssistant::answer()` now retrieves before it builds the prompt: `Retriever::retrieve($question, RetrievalScope, k: 5)` returns up to five passages, best first, and `ContextAssembler::context()` renders them through `ContextBlock` as `[article-slug › Section]` labelled passages under a one-line preamble with the docs version. The question stays last. Retrieval is unconditional (no `search_help_center` tool: the chapter only suggests it as Exercise 5).
- `App\Ai\Retrieval\PgRetriever` runs the hybrid query: a vector side (cosine on a `halfvec` cast, top 20) and a keyword side (`websearch_to_tsquery` on the generated `search` column, top 20) merged by reciprocal rank fusion with constant 60. A passage is kept when its cosine similarity is at least the floor (`ai.retrieval.similarity_floor`, `AI_RETRIEVAL_FLOOR`, default 0.70) or the keyword side found it; an empty result is valid. Filters run inside both sides: the latest ingested `help_version`, the customer's plan against `tags.plans` (untagged chunks are visible to every plan), and the area when the classifier is sure (`TicketCategory::areaIfConfident()`: only `account`, because the Chapter 9 classifier returns no confidence and `billing` spans four help areas). Differences from the book: the floor is applied to up to 20 merged candidates rather than to the first 5, so the cap is filled with the best passages above the floor; the similarity is computed for every candidate in the final select; `tags` is `jsonb` (the book writes `json` but queries it with `?`); `RetrievalScope::$tenantId` is carried but not used to filter, because the help center is shared by every tenant (the row-level security sketch in Topic 9 is not built for the same reason).
- `help:ingest [--docs-version=] [--force]` (the book writes `--version`, which Symfony reserves). Migration `2026_01_13_000000_add_production_columns_to_help_chunks_table.php` adds `title`, `heading_path` (`Billing › Understanding late fees › Section`), `tags` (front matter `plans`/`audience` as lists, plus `area`), `help_version`, `source_modified_at`, a unique `chunk_key` (sha1 of source, heading path and position), the generated `search` tsvector with a GIN index, and replaces the `vector` HNSW index with a `halfvec` one (`m = 16`, `ef_construction = 96`). Unchanged chunks keep their embeddings and only get the new `help_version`. Boilerplate regexes live in `ai.ingestion.boilerplate_patterns` (the help center has none today, so they are a no-op on the shipped articles). `help:embed` and `help:search` keep working on the new schema.
- `SupportPrompt` is v6 (`2026-11-09.6`): the rules block adds "answer only from the provided context, cite the label of each passage, do not combine passages" and a note that tool answers need no citation. `SupportPrompt::escapeHatch()` is the fixed fallback reply.
- `CitationChecker` (no model): every bracketed label must be in the turn's label map; every factual sentence (digit or policy word) must carry a citation; a cited passage must contain the sentence's numbers (compared numerically) or share key terms. One repair turn (`RepairPrompt::citations()`), then the escape hatch. The citation requirement is skipped when no passages were retrieved or the answer came from a tool result; a fabricated label is flagged either way. The JSON response gains `sources` (`label`, `url`) and `citations_ok`; `support:ask` prints the sources.
- Data: `message_sources` (which chunks each reply cited), `model_calls.citation_errors` (null when not checked), `ai:stats` prints the citation flag rate and warns when it rises 10 points above the 7-day figure. `AI_SEMANTIC_CACHE_REQUIRE_GROUNDING` now defaults to true: only answers that came with retrieved passages and a clean citation check are stored (`phpunit.xml` sets it false so the Chapter 14 cache tests keep exercising the cache without passages).
- `retrieval:eval` and `storage/golden/retrieval.jsonl` (120 questions written against the shipped articles: 108 with their answering chunks, 12 off-topic). `--mode` and `--floor` cover Exercises 1 and 2.
- Chunk labels use the first section of a merged chunk, so many chunks are labelled `slug › Introduction`; those link to the article without an anchor. Help pages now give every `##` heading an `id` so the other links resolve.
- Verified only against `Http::fake()` and a Postgres test database: the grounded, repaired and escape-hatch paths, the plan and area filters, ingestion diffs, the eval arithmetic. Nothing in the tests needs a model.

## ch14

- Prompt and context optimization. `App\Ai\Context\ContextAssembler` builds every support prompt from named slots in one fixed, stable-first order: system (with the per-user memories block inside it), the summary note, history, a context block, then the question. It records tokens per slot (`system`, `memories`, `summary`, `history`, `context`, `question`; `ToolRunner` adds `tools` and, after a tool round, `tool_results`) and returns an `AssembledPrompt` (`messages`, `breakdown`, `overBudget`). Slot caps live in `ai.slot_budgets` (memories 150, summary 400, context 3,500); the context slot drops whole trailing chunks to fit, the others only report `overBudget`. `SupportPrompt::messages()` is now a thin call into the assembler and `SupportPrompt::assemble()` returns the `AssembledPrompt`; the context block is its own user message and is left out when there are no chunks (the old "(no context provided)" line and the `Question:` label are gone, as in the book's figure).
- Cache breakpoints: `ProviderCapabilities::supportsCacheBreakpoints()` is the one provider-specific branch. When true (`AI_PROVIDER=anthropic`, or `AI_CACHE_BREAKPOINTS=true`), the system message and the summary note carry `cache_control: {"type": "ephemeral"}`. Ollama and the other OpenAI-compatible servers get none. Tool definitions are now emitted sorted by name so their bytes cannot depend on registration order.
- `SupportPrompt` is v5 (`2026-11-09.5`). The rules were edited per Topic 5 (hedges and rationales cut, rules merged). Measured with this repo's counters, the base system text went from 346 to 302 tokens with the ratio counter and from 269 to 228 with tiktoken. The book's 610 to 440 describes its own v3 text, which this repo never had.
- Migration `2026_01_11_000000_add_context_columns_to_model_calls_table.php` adds `model_calls.cached_tokens`, `cached_tokens_estimated`, `ttft_ms`, `context_breakdown` (JSON) and `semantic_cache_hit`. `ModelCalled` gained `cachedTokens`, `ttftMs`, `contextBreakdown`, `semanticCacheHit` and, beyond the book, `cachedTokensEstimated` so a provider figure can be told from a local estimate. `AiHttpClient::chat()` takes a `CallDetails` (breakdown and cache flag), uses `usage.prompt_tokens_details.cached_tokens` when the server reports it, and otherwise estimates with `PrefixCacheEstimator` (characters shared with the previous call of the same feature in the same conversation, counted as tokens, capped at the reported prompt tokens; the previous prompt is kept in the cache store for `ai.prompt_cache.prefix_memory_minutes`). Calls without a conversation have no estimate. `stream()` records `ttft_ms` at the first non-empty delta; `support.reply` is not streamed at this chapter, so its `ttft_ms` is null.
- Semantic cache: migration `2026_01_12_000000_create_cached_answers.php` (the book's columns plus a composite index), `CachedAnswer`, `SemanticCache` (`lookup`, `lookupAnyCacheable`, `store`, `recordHit`), `CachePolicy`, `HelpVersion`, `SupportCacheGate`. `SupportAssistant::answer()` asks the gate first: on a hit it answers with no chat call (a `model_calls` row with provider `semantic-cache`, zero tokens, `semantic_cache_hit` true, and the user and assistant turns are stored in the conversation); on a miss it runs as before and may store the answer. Config: `ai.semantic_cache` (`enabled` from `AI_SEMANTIC_CACHE`, `thresholds` `howto` 0.92, `ttl_days` 30, `require_grounding` from `AI_SEMANTIC_CACHE_REQUIRE_GROUNDING`). Differences from the book's figure: the nearest-neighbour lookup runs before the classifier, so a hit costs one embedding call and no classifier call (the matched row already carries the category the classifier gave an earlier, near-identical question); only `howto` is cacheable because the Chapter 9 classifier has no `policy` label (`billing` mixes policy and account status); `lookup()` returns an empty `CachedAnswer` (check `exists`) instead of `null`.
- Scoping, so one customer's answer cannot reach another: the cache is only read or written for a user with a customer; every automatically stored row has `tenant_id` set to the asker's customer and `store()` throws `CacheScopeRequired` for a null tenant; a row is visible to its own tenant, or to everyone only when `tenant_id` is null and a human set `status` to `approved` (`cached-answers:review --approve=ID --share`, which refuses answers or questions containing an email, a digit, an invoice reference or a decline phrase). Only a first turn is eligible (a follow-up may lean on earlier turns); the question must be generic (no `my`/`our`/`we`/`this`/`that`, digits, emails, month names, `today`); the answer is stored only when the run made exactly one model call and no tool call, the user has no memories block, the answer is not a decline or escape-hatch reply, and carries no invoice number, ticket number or email address. Rows carry `help_version` and expire after `ttl_days`.
- Commands: `ai:stats`, `support:ask`, `support:ask-batch` (reads `storage/samples/howto.json`, an object with a `questions` list; `-v` prints a line per question) and `cached-answers:review`. `ai:stats` prints the window and the 7-day figures side by side. The "per category" split and the thumbs-down count from the book's figure are not built: `model_calls` has no category column and the app has no feedback input yet.
- Tests: `tests/Unit/Ai/Context/*`, `tests/Unit/Ai/Cache/*`, `tests/Unit/Ai/Stats/*`, `tests/Unit/Ai/Support/QuestionBatchTest.php`, `tests/Feature/Ai/Cache/*` (tenant isolation, thresholds, version, expiry, shared-only-when-approved, end to end through `POST /support/ask`), `tests/Feature/Ai/ContextBreakdownTest.php`, and the four command tests. The test environment sets `AI_SEMANTIC_CACHE=false` in `phpunit.xml` so older tests keep their one-call fakes; the cache tests turn it on. Every model and embedding reply in the tests is faked.
- Not built: sentence-window compression and old-assistant-turn dropping (they belong with retrieval and the history window; the context slot only trims whole chunks), context distillation, the DSPy-style optimizer (exercise 5), a dashboard page. With no retrieval until Chapter 15, an ungrounded how-to answer is a decline on a small local model and is correctly not cached; set `AI_SEMANTIC_CACHE_REQUIRE_GROUNDING=true` once the assistant passes retrieved chunks.

## ch12

Tab, newline and pipe characters inside a value are flattened or escaped so a row cannot be split by its own data.

Today is YYYY-MM-DD.` is stated once; the limit is 25 (the constructor takes another). The tickets opened by the assistant do not dispatch `TicketReceived`.
- `SupportAssistant::answer($user, $question, $contextChunks = [], $conversationId = null)` now returns a `ToolRunResult`; `SupportPrompt` is v3 (`2026-11-09.3`): it adds the tools paragraph from the book and says tool results are a source of account facts. `POST /support/ask` now answers `{answer, truncated, rounds, hit_cap, pending}`.

## ch10
